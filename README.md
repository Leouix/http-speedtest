# HTTP Speed Test

Консольная утилита на Python, которая замеряет скорость скачивания по HTTP(S):
делает N последовательных запросов к одному адресу, каждый раз дочитывает ответ
до конца, затем печатает время каждого запроса, суммарный объём и скорость.

Зависимостей нет — только стандартная библиотека Python.

## Требования

- Python 3.9 или новее

## Запуск

```bash
git clone https://github.com/Leouix/http-speedtest.git
cd http-speedtest

# 10 запросов к тестовой картинке (значения по умолчанию)
python3 speedtest.py https://asialive.news/test-image

# свой адрес, своё число запросов и таймаут
python3 speedtest.py https://example.com/big-file.jpg -n 5 -t 60
```

| Флаг | Значение по умолчанию | Что делает |
|------|----------------------|------------|
| `url` | — | адрес, который скачиваем (позиционный аргумент) |
| `-n`, `--runs` | `10` | количество последовательных запросов |
| `-t`, `--timeout` | `30` | таймаут одного запроса, секунды |
| `--cache-bust` | выключен | добавляет уникальный `?run=...` к каждому запросу, чтобы обойти кэш CDN |
| `--json` | выключен | печатает итог в JSON (для скриптов и CI) |

Коды выхода: `0` — все запросы успешны, `1` — не удался ни один, `2` — часть
запросов упала.

## Единицы измерения

- **Скорость — Mbit/s (мегабит в секунду)**, десятичные: 1 Mbit/s = 1 000 000 бит/с.
  Это те же единицы, в которых операторы связи и Speedtest.net указывают скорость
  канала. В скобках рядом печатается то же значение в **MB/s**: 1 MB/s = 8 Mbit/s.
- **Объём — MB и KB, десятичные**: 1 MB = 1 000 000 байт, 1 KB = 1 000 байт
  (не MiB/KiB).
- **Время — секунды** с точностью до миллисекунды.

Формула скорости:

```
бит/с = скачано_байт × 8 / затрачено_секунд
```


## Как считаются цифры

1. Запросы идут **строго последовательно**: следующий стартует только после того,
   как предыдущий ответ дочитан до конца.
2. Таймер запускается перед запросом и останавливается после последнего байта
   тела. То есть в замер входят DNS, установка TCP-соединения, TLS-хендшейк,
   ожидание первого байта и передача тела — именно то время, которое чувствует
   пользователь.
3. Тело читается блоками по 64 КиБ, поэтому 20-мегабайтный файл не занимает
   память целиком. Количество байт считается по факту, а не берётся из
   `Content-Length`; если сервер прислал не столько, сколько обещал, скрипт
   предупредит об этом в stderr.
4. Отправляется `Accept-Encoding: identity`, чтобы сервер не отдавал сжатый
   ответ: иначе «скачанные байты» зависели бы от сжимаемости файла.
5. Две разные скорости в итоге:
   - **Average speed** — среднее арифметическое скоростей отдельных запросов
     (сколько реально качается один запрос);
   - **Overall speed** — весь объём / всё время (устойчивее к разбросу и включает
     паузы между запросами).
6. Соединение на каждый запрос новое (нет keep-alive), поэтому в каждом замере
   есть фиксированная плата за TLS-хендшейк — на медленных запросах это заметно.

## Тесты

Тесты не ходят в интернет: поднимают локальный HTTP-сервер и проверяют подсчёт
байт, обработку 404 и математику итогов.

```bash
python3 -m unittest discover -s tests -v
```

## Ограничения

- Один TCP-поток на запрос: при большом RTT и потерях пакетов такой поток не
  насыщает канал. На гигабитном подключении цифра будет заниженной — нужен
  параллельный вариант или несколько потоков.
- CDN и прокси могут отдавать файл из кэша, а не с диска; `--cache-bust` частично
  решает это, но тогда каждый запрос идёт мимо кэша.
- Измеряется только скачивание: upload, ping и jitter не затрагиваются.
- Разброс на Wi-Fi большой (в примере 3,2–9,1 Mbit/s), поэтому для стабильной
  цифры лучше провод, 5+ минут прогона и медиана вместо среднего.
